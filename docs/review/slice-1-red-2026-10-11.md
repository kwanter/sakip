## Public request and fixture prerequisites

`tests/Feature/AdminProtectedAccountTest.php` creates a verified manager with
the direct permissions `admin.dashboard` and `manage-users`, without the
Super Admin role. It separately creates a verified target holding the reserved
Super Admin role and two institutions. Permission cache is cleared. Every test
checks the actor permissions, role identities, and original password validity.
No authorization, HTTP middleware, database persistence, or audit sink is mocked.

The attack uses `PUT /admin/users/{target UUID}` via `admin.users.update`:

```php
[
    'name' => 'Updated Test Account',
    'email' => 'updated-'.$target->id.'@example.test',
    'password' => 'Replacement-Test-Password-456!',
    'password_confirmation' => 'Replacement-Test-Password-456!',
    'email_verified' => '1',
    'instansi_id' => $destination->id,
]
```

Passwords above are disposable test constants. Both institutions exist, the
email is unique per target, and password confirmation matches. Every update
asserts that no validation errors occurred before evaluating security outcomes.

## Observed RED evidence

| Security assertion | Observed failure |
| --- | --- |
| Update must return 403 | Expected 403; received 302 |
| Password hash remains identical | Refreshed hash equality was false |
| Identity and institution remain unchanged | All three values were replaced |
| Replacement login cannot access target | Login authenticated the target UUID |

The login regression logs out the manager, flushes the session, and verifies
guest status before submitting the replacement credentials to `/login`.
Its failing UUID inequality demonstrates authentication as the Super Admin
target, rather than a residual manager session. Separate tests prevent the
first status failure from hiding persisted-state and authentication evidence.

The identity regression confirms role membership survives the attack before
its identity assertion fails. This preserves the privileged role on the
compromised account. No unrelated 500, 422, fixture error, or missing-method
failure was observed.

## Positive controls and counterevidence

- A delegated manager successfully updates an ordinary account through the
  same HTTP route, with persisted name, email, institution, password, and a
  real `user.updated` audit entry verified.
- A Super Admin successfully updates its own credentials through the same
  route, retains its reserved role, and creates an audit entry.
- Both existing role-escalation tests remain green. Their service-level
  prohibition on granting the reserved role does not protect an existing
  Super Admin account against credential replacement.
- Real authentication is reproduced only in the disposable test environment;
  this execution does not establish production exposure.
